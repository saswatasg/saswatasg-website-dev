FilmRisk.AI explores whether public film data can support a pre-release risk score. The published evaluation did not establish a useful predictive advantage. That finding changes how the project should be presented: as an evaluation experiment, rather than a successful greenlight decision engine.
</AnswerBox>

## The product question

A score is only useful if it improves the decision someone could make without it. For a film-risk product, an attractive interface or a complicated model does not establish that improvement. The relevant question is whether the prediction adds reliable information before release, using inputs available at that time.

The project combines a gradient-boosted model with empirical Bayesian priors and a component-based scoring approach. Its implementation is in TypeScript with a Next.js interface. Simulation can describe uncertainty under assumptions, but it cannot repair missing data or prove that a score is commercially useful.

## Data coverage is part of the result

The repository documents 2,454 film records spanning 2001–2025. Only 729 have the financial information required for training. This is not a representative financial history of every film in the period. It is a subset shaped by which figures were publicly reported and could be assembled.

That missingness creates a practical constraint: the product must not imply that a score describes the whole industry equally well. Dataset size, the training subset and the population a model can reasonably speak about are different things.

## Test on later films, not shuffled familiarity

The published primary evaluation uses 14 rolling annual folds with 658 tested films. This temporal approach asks whether knowledge from earlier releases helps with later releases. It is more relevant to a pre-release decision than simply demonstrating a fit to familiar records.

Outcome-derived concept features were removed from the evaluation to address leakage. User-supplied pre-release concept inputs in the product are not thereby validated by that historical test. The distinction matters because the implemented interface and the tested prediction path need not be identical.

## What the benchmark actually says

The published results report 29.3% classification accuracy, compared with 63.7% for a band-median baseline and 80.5% for an always-flop baseline. Greenlight precision was 11.3%, against a base hit rate of 11.0%. Reported RMSE was 1.303, compared with 1.23 for the band-median baseline.

These metrics answer different questions; they should not be collapsed into a single success percentage. In particular, high accuracy from predicting a dominant class is not a useful recommendation system. Conversely, these results do not justify marketing the more complex model as superior. They are published repository results, not an independently reproduced evaluation in this portfolio audit.

## What I would require before expanding it

The next work should improve provenance, establish a decision-relevant baseline and test the exact inputs used before release. A larger interface or more model components should follow evidence of usefulness, rather than substitute for it. A small recent holdout also needs its sample size made visible.

The portfolio value here is the willingness to expose an unfavorable result and change the claim. This remains a research experiment. It should not be used as a validated financial decision tool.

The implementation, benchmark and limitations are available in the [FilmRisk.AI repository](https://github.com/saswatasg/FilmRisk.AI) and its [published benchmark results](https://github.com/saswatasg/FilmRisk.AI/blob/main/src/generated/benchmark-results.json).
